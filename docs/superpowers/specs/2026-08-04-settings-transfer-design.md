# 設定の書き出し・読み込み 設計

## 目的

人格を含むMuchioLLMの設定を、カテゴリ単位でJSONへ書き出し、別環境へ安全に読み込めるようにする。現在の設定フォームに機能を埋め込まず、サイドバーから独立した「設定を移す」画面として見つけやすくする。

## 対象範囲

- 設定カテゴリの選択式JSON書き出し
- JSONファイルの選択式読み込み
- 読み込み前の現在の`config.json`バックアップ
- 読み込み時の型・範囲・文字数の検証
- 競合防止のための設定mtime確認
- Supabaseキーなど秘密情報の転送除外

会話履歴、日記、声紋、成長データなどの`data/`配下のデータ移行は対象外とする。

## UI設計

### ナビゲーション

既存サイドバーに「設定を移す」を追加する。クリックすると、設定フォームとは独立した転送画面だけを表示する。

### 画面構成

```text
┌ 設定を移す ──────────────────────────────────┐
│ 人格や話し方を別のMuchioへ持っていけます。    │
│                                                │
│ ┌ 書き出す ─────────┐ ┌ 読み込む ─────────┐ │
│ │ [全選択] [全解除]  │ │ JSONファイル選択   │ │
│ │ ☑ なまえ           │ │ [ファイルを選ぶ]   │ │
│ │ ☑ じんかく・せいかく│ │ ☑ なまえ            │ │
│ │ ☑ じんかく・口調    │ │ ☑ じんかく・せいかく │ │
│ │ ...                │ │ ...                │ │
│ │ [JSONを書き出す]   │ │ [選択した設定を読み込む]│
│ └───────────────────┘ └──────────────────┘ │
│ ※秘密情報は書き出しません。                  │
└──────────────────────────────────────────────┘
```

カテゴリはバックエンドが返す定義を共用し、書き出しと読み込みで同じ選択肢を表示する。初期状態は全カテゴリ選択とする。選択が空の場合は操作を実行せず、何を選ぶべきかをトーストで示す。

書き出しはブラウザのダウンロードとして`muchiko-settings.json`を保存する。読み込みはファイル選択後に対象カテゴリを確認し、現在設定がバックアップされることを確認ダイアログで明示する。

## データ形式

```json
{
  "format": "muchiko-settings",
  "version": 1,
  "exported_at": "2026-08-04T12:00:00+0900",
  "categories": ["persona-free-text", "persona-examples"],
  "settings": {
    "persona": "...",
    "persona_en": "...",
    "persona_weight": "mid",
    "examples": "...",
    "examples_en": "..."
  }
}
```

`categories`は書き出し元の選択を記録する。読み込み時にUIでカテゴリを選んだ場合、その選択を優先し、ファイルに含まれる他カテゴリや選択外のキーは変更しない。旧形式として、トップレベルに設定キーを直接持つ`config.json`も読み込めるようにする。

## バックエンド設計

### カテゴリ定義

`muchio_llm.py`にカテゴリID、表示名、所属キーの定義を置く。人格は次の4カテゴリに分ける。

- `persona-character`: 性格スライダー
- `persona-talk`: 話し方スライダー
- `persona-preferences`: こだわりルール
- `persona-free-text`: 自由テキスト、英語人格、効きぐあい
- `persona-examples`: 例文

既存設定キーのうち定義にないものは「その他」にまとめ、設定追加時に転送から漏れないようにする。ただし秘密情報の除外リストを優先する。

### エンドポイント

- `GET /settings_export?categories=...`
  - 選択カテゴリの値だけをJSONで返す。
  - `Content-Disposition`で`muchiko-settings.json`をダウンロードさせる。
- `POST /settings_import`
  - JSON本文、選択カテゴリ、現在の`cfg_mtime`を受け取る。
  - 形式を検証し、許可されたカテゴリのキーだけを現在設定へマージする。
  - 既存`config.json`を`config.<timestamp>.import.bak`へコピーしてから保存する。
  - 成功時は新しいmtimeとimported/ignoredキーを返す。
  - mtimeが古ければ409、形式や値が不正なら400を返す。

### 値の検証

現在値または既定値から型を判定し、数値は既存設定UIと同じ範囲へ補正する。文字列は既存保存処理と同等の最大長で切り詰め、`mode`と重み設定は許可値以外を拒否する。不明キー、秘密情報、選択外カテゴリのキーは無視して一覧に返す。

秘密情報として少なくとも次を転送対象から除外する。

- `peer_supabase_url`
- `peer_supabase_key`
- `peer_room`

## フロントエンド設計

`ui/index.html`に独立セクション、`ui/app.js`にカテゴリ描画・ダウンロード・ファイル読み込み処理、`ui/style.css`に転送画面専用のレイアウトを追加する。既存の設定保存フォームやカテゴリトグルとは別の状態として管理する。

エラー状態は次のように具体的に伝える。

- ファイル未選択: 「読み込むJSONファイルを選んでください」
- カテゴリ未選択: 「読み込むカテゴリをひとつ選んでください」
- 形式不正: サーバーのエラー内容を表示
- 競合: ページを再読み込みしてから再試行するよう案内
- 成功: 書き出しカテゴリ、読み込み項目数を表示

## テスト方針

実装前に次の失敗テストを追加する。

1. カテゴリ定義が人格5カテゴリと秘密情報除外を含む。
2. 書き出しペイロードが形式、バージョン、カテゴリ、選択キーだけを含む。
3. 読み込みが選択カテゴリだけをマージし、選択外キーを変更しない。
4. 不正な型・範囲・モード値を拒否または既存ルールどおり補正する。
5. 読み込み前にバックアップを作成する。
6. UIに独立した設定転送画面と書き出し・読み込み操作が存在する。

既存の`test_muchio.py`と`test_ui_config.py`を使い、Pythonの標準テスト実行で確認する。ブラウザ側の操作は静的HTML/JavaScriptの契約テストに加え、可能なら設定UIを起動してPlaywrightでダウンロードと読み込みの表示状態を確認する。

## 完了条件

- サイドバーから設定転送画面を開ける。
- 人格関連カテゴリだけを選んでJSONを書き出せる。
- 別環境でJSONを選び、人格関連カテゴリだけを読み込める。
- 読み込み前の設定がバックアップされる。
- 秘密情報がJSONに出ない。
- 全テストが通り、既存の設定保存・人格生成動作に影響がない。
