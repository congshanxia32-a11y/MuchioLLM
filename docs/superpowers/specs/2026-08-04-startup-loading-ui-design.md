# 起動時設定読み込みローディングUI 設計

## 目的

`run.bat` 起動後、設定UIが `/bootstrap` から設定値を受け取るまでの待ち時間を明示する。利用者が、画面が固まっているのか、起動に失敗したのかを判断できる状態にする。

## 採用方針

既存の静的HTMLを表示したまま、設定取得中だけ全画面オーバーレイを重ねる。`/bootstrap` の成功後にオーバーレイを隠し、既存の `applyBootstrap()` と画面初期化をそのまま利用する。スケルトンUIやサーバー起動待ちのポーリングは今回の範囲に含めない。

## UI構成

- `ui/index.html` にローディングオーバーレイを追加する。
- オーバーレイには、アプリ名、短い説明、「設定を読み込んでいます…」の文言、CSSスピナーを表示する。
- 設定取得中はオーバーレイを表示し、背後のフォーム操作を遮断する。
- `aria-live="polite"` と `role="status"` を使い、状態変化を支援技術へ伝える。
- 既存のダークテーマ・ライトテーマ双方で読める色とする。
- 完了時は短いフェードアウト後に `hidden` とし、レイアウト上からも除外する。

## データフロー

1. HTMLの初期表示時はローディングオーバーレイを表示する。
2. `app.js` の `loadBootstrap()` 開始時に読み込み状態を明示する。
3. `/bootstrap` が成功したら `applyBootstrap()`、`maybeStartTour()` を実行する。
4. 初期化完了後、ローディング状態を完了へ更新し、オーバーレイを閉じる。
5. `/bootstrap` が失敗した場合は、エラー文と再試行ボタンを表示する。再試行では同じ `loadBootstrap()` を呼び、成功するまでオーバーレイを閉じない。

## エラー処理

- ネットワークエラー、HTTPエラー、JSON解析エラーをすべて初期化失敗として扱う。
- HTTPステータスが成功でない場合は例外化し、画面に汎用的なエラー文を表示する。
- 再試行中はボタンを無効化し、通常の読み込み文言に戻す。
- 既存のトースト通知も残すが、初期化失敗の主な案内はオーバーレイ内で行う。

## 変更対象

- `ui/index.html`: オーバーレイと再試行ボタンのマークアップ
- `ui/style.css`: オーバーレイ、スピナー、表示状態、テーマ対応、フェード
- `ui/app.js`: 読み込み状態更新、HTTPエラー判定、再試行イベント、完了時のクローズ
- 必要に応じて既存のUI静的チェックへ、要素と起動フローの検証を追加する

## 検証

- 既存のPythonテストを実行し、設定・bootstrap契約を壊していないことを確認する。
- HTML/CSS/JSにローディング要素、状態クラス、再試行処理が存在することを静的に確認する。
- ローカルUIを起動できる場合は、`/bootstrap` 成功時にオーバーレイが消えること、失敗時に再試行UIへ切り替わることをブラウザで確認する。
